# Building the documentation book

The book lives under `docs/book/` and is built with
[Jupyter Book](https://jupyterbook.org). Its toolchain is isolated from the
project's conda environment (heyoka is conda-only and not needed to build
the book, since notebooks are embedded with their already-computed outputs,
not re-executed).

```
python -m venv docs/.venv
docs/.venv/Scripts/pip install -r docs/requirements.txt   # docs/.venv/bin/pip on macOS/Linux

docs/.venv/Scripts/python docs/sync_examples.py           # copies the example notebooks into docs/book/examples/
docs/.venv/Scripts/jupyter-book build docs/book

# open docs/book/_build/html/index.html
```

`docs/sync_examples.py` must be re-run (and the book rebuilt) any time a
notebook changes under `examples/`, since `docs/book/examples/` is just a
gitignored copy used to keep the book's source root inside `docs/book/`. A
new example folder is picked up automatically; it only needs an entry in
`docs/book/_toc.yml`.

The schematic figures of the theory chapters are generated by
`docs/make_figures.py`, run with the project environment, and committed
under `docs/book/figures/`, so the book builds without matplotlib.

## Publishing

The published book, at <https://giovannifacchinetti99.github.io/ios-mission-planner/>,
is built and deployed automatically by
[`.github/workflows/docs.yml`](../.github/workflows/docs.yml) on every push to
`master` that touches `docs/` or `examples/`. The workflow repeats the same
steps as above (install `docs/requirements.txt`, run `sync_examples.py`,
`jupyter-book build docs/book`), then adds a `.nojekyll` file to the built
`docs/book/_build/html/` before uploading it as the Pages artifact. Without
that file, GitHub Pages runs the output through Jekyll, which ignores any
folder starting with an underscore, including `_static/` and
`_sphinx_design_static/`, the folders holding the Sphinx Book Theme's
JavaScript and CSS. The sidebar then renders unstyled and its toggle, search,
and current-section highlighting stop working, even though a local build
looks fine, since a local build never goes through Jekyll.
